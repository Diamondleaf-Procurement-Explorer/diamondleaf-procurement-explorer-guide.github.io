Diamondleaf Public Procurement Explorer

This page provides orientation and guidance for understanding the analytics presented in the Diamondleaf Public Procurement Explorer.

What this explorer shows

The Explorer aggregates and visualizes publicly available European public procurement notices, enabling structured analysis across countries, sectors, and procurement procedures.

The data reflects what has been published in official procurement systems. It does not represent real-time contract execution or financial settlement.

Data domains and reference layers

The Explorer is built on multiple source-aligned schemas that combine procurement data with supporting reference and contextual layers. This structure allows users to move from raw published notices to more structured interpretation while preserving traceability to the original source systems.

Operational datasets are complemented by reference layers such as code lists, business term definitions, API field mappings, legal context, classification systems, and derived statistical indicators. This separation keeps the system transparent while reducing the need to interpret raw technical fields directly.

  • DIAMONDLEAF_PLATFORM_DATA_QUALITY_AND_SYSTEM_STATE
    Provides context on data availability, completeness, and system state.
  • ENTERPRISE_EUROPE_NETWORK
    Company and partnership-related data providing additional market context.
  • TENDERS_ELECTRONIC_DAILY
    Core EU procurement notices, including procedures, awards, and metadata.
  • NORTH_ATLANTIC_TREATY_ORGANIZATION
    Procurement-related data extending coverage into NATO environments.
  • EU_NOTICES_CODELIST_REFERENCE_DATA
    Standardized code lists for consistent interpretation of procurement data.
  • EU_NOTICES_BUSINESS_TERM_FIELD_LIST_REFERENCE_DATA
    Official business terms linking procurement concepts to technical fields.
  • EU_NOTICES_API_FIELD_REFERENCE_DATA
    Documentation of source API fields and structures.
  • REGULATORY_AND_LEGAL_FIELD_REFERENCE_DATA
    Legal and regulatory mappings supporting interpretation and compliance.
  • STATISTICAL_CLASSIFICATION_NOMENCLATURES
    Classification systems such as CPV, NACE, and NUTS.
  • STATISTICAL_INDICATORS
    Derived metrics and indicators for structured analysis.

How to read the analytics

Procurement processes consist of multiple notice types (e.g. planning, contract award, modification). Dashboards may therefore reflect different stages of the same procurement lifecycle.

Aggregated figures should be interpreted as indicators of activity and structure, not as exact financial totals.

Navigation overview

  • Use filters to scope results by country, sector, or procedure
  • Dashboards are grouped by notice and form type
  • Hover and drill-down features reveal additional context

Limitations & caveats

Public procurement data is subject to reporting practices, legal constraints, and publication delays. Differences between dashboards may reflect regulatory structure rather than inconsistencies.
